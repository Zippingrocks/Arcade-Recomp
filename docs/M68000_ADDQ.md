# Native MC68000 ADDQ to data registers

Date: 2026-10-12. Scope: byte, word and long ADDQ with immediates 1–8 and
data-register destinations. Instructions are fixed ahead-of-time translations;
address-register and memory destinations remain outside this bounded batch.

## Primary architecture source

Motorola's [M68000 Family Programmer's Reference Manual](https://www.nxp.com/docs/en/reference-manual/M68000PM.pdf),
printed 4-11 through 4-12, defines the three-bit quick immediate, including
encoded zero meaning eight. A sized data-register operation replaces only the
selected byte/word/long and sets X equal to carry, N from the result sign, Z
from zero, V on signed overflow and C on unsigned carry.

The runtime requires every input bit in the selected width to be known before
it computes a result. It never guesses carry or overflow from partial state.
Byte and word operations preserve both the value and knownness of upper data
register bits. Invalid widths, registers or immediates stop atomically.

## Verification and original-byte evidence

Three ROM-free native tests cover all 192 encodings in this subset, every one
of the 256 byte inputs, all quick values and registers, selected word/long
boundaries, independent carry/overflow flag calculation, upper-register
preservation, unknown operands and invalid helper arguments. All 48 MC68000
tests pass under GCC/UBSan. The authenticated generated sound source passes
strict Clang syntax checking at `-O2 -Wall -Wextra -Werror`.

The original sound chip authenticates as SHA-1
`1edaed489a3518ddad85728e416319f940ea02bb`. Both `0x600228` and `0x60044A`
contain `0x5002`, `ADDQ.B #8,D2`, and now translate. The reset-vector static
graph grows from 108/100 to 116/108 discovered/translated sites. Eight
unsupported sites remain because the added paths reveal two genuine
LEA-with-displacement stops at `0x600242` and `0x60044C`; together with
`0x6021B6`, they identify the next three-site instruction family.

Continuous execution remains unchanged: strict mode completes 17 instructions
before the unimplemented SCSP read at `0x100401`; the documented SCSP-control
opt-in completes 18 before the unimplemented board write at `0x400001`. No
device response, RAM, cabinet timing or audio behavior is fabricated. Sound
CPU remains 5%, audio remains 0%, and overall original HOTD1 remains 10%.
Gates A/B/C remain open.
