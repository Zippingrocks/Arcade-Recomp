# Sega 315-5649 serial I/O: independent original HOTD1 research

**Status: PARTIAL, SYNTHETIC-TESTED. NOT arcade-hardware verified or a complete I/O chip.**

## Original arcade target and evidence

The primary artifact is the verified **`hotdo` original Sega Model 2C arcade revision**, not `hotd` Revision A and not the Windows/Saturn adaptations. The user's private ROM set was previously confirmed against 29 published chip fingerprints. Proprietary program and asset bytes are **not** checked into this repo.

There are two independent kinds of evidence here:

1. **ROM-observed commands.** Local static i960 disassembly of the authentic original `hotdo` startup addresses, recorded below. This establishes what the game *requests*, not how physical I/O devices responded.
2. **Published hardware register maps.** Model 2C's memory map associates `0x01c00000..0x01c0001f` with a Sega 315-5649 device on 8-bit lanes in a 32-bit i960 word. Historical service-document annotations and MAME's I/O inventory name its register functions. These descriptions are *references*, not software to copy.

### Original startup path

| Original HOTD1 i960 address | Verified static observation | Why it matters |
| --- | --- | --- |
| `0x0000068c` | `CALL` to `0x000a3750` | Enters arcade I/O setup |
| `0x000a3750` | Load base `0x01c00000` | Addresses Sega I/O aperture |
| `0x000a375c` | Byte write to `0x01c00014` of `0xff` | Channel 2 serial TX command |
| `0x000a3764` | Byte write to `0x01c00012` of `0x01` | Channel 1 serial TX command |
| `0x000a3768` | `CALL` to `0x000a3720` | Polls for both RX buffers |
| `0x000a376c` | Byte read from `0x01c00016` | Channel 1 RX byte |
| `0x000a3770` | Byte read from `0x01c00018` | Channel 2 RX byte |

This is a *static* reconstruction from the original program's instructions. **The revised native implementation has not yet been shown executing this specific original-ROM sequence with correct physical device responses.**

### Verified waiting loop at `0x000a3720`

At `0x000a3720`, the program loads the I/O base, prepares the mask `0x0c`, reads the status byte at offset `0x1a`, masks that byte with `0x0c` and loops until the masked result equals `0x0c`. It then returns to the caller, which reads the two serial RX bytes. The register inventory labels bits 2 and 3 of the serial status as *RX1/RX2 buffer full*.

**Important:** `0x0c` is the status condition the game *waits for*. It is **not** a valid justification for making every status read return `0x0c`. Some existing emulation code uses that shortcut. ArcadeRecomp deliberately does not.

## CPU address / 315-5649 register mapping

The Model 2C bus maps the 8-bit device to even CPU-byte addresses, consistent with a 32-bit I/O lane mask of `0x00ff00ff`. We currently support:

| i960 physical address | Chip register | Meaning | ArcadeRecomp behavior |
| --- | --- | --- | --- |
| `0x01c00012` | `0x09` | RS422 TX1 | Records transmitted byte and notifies an optional output consumer |
| `0x01c00014` | `0x0a` | RS422 TX2 | Records transmitted byte; input-handler/multiplexer integration is future work |
| `0x01c00016` | `0x0b` | RS422 RX1 | Requires an explicit external provider; otherwise throws |
| `0x01c00018` | `0x0c` | RS422 RX2 | Requires an explicit external provider; otherwise throws |
| `0x01c0001a` | `0x0d` | RS422 status | Requires an explicit external **status** provider; never fabricates ready bits |

Other registers include digital I/O, direction settings, serial mode and an analog multiplexer. Their behavior is **not implemented**. Even-byte addresses are selected only under the documented device layout; odd or wide accesses are refused pending stronger evidence.

## Our independent implementation

- `runtime/sega3155649_serial.hpp` is a dedicated, original serial interface, with an explicit event stream and two independent channel states.
- `runtime/model2c_bus.hpp` provides opt-in serial TX support; the **default remains fully strict**, rejecting even documented serial writes until explicitly enabled.
- No missing serial receive byte or status is replaced by a guessed constant. An injected input/status provider is for hardware integration or a **clearly labeled synthetic fixture**.
- Native translated byte loads/stores use dedicated 8-bit bus callbacks, not 32-bit RAM substitution.
- `tools/hotd1_strict_boot_probe.cpp` can opt into known serial writes using `--serial-tx`. It logs transmitted bytes and stops when status or another unimplemented hardware device is needed.
- `tests/test_sega3155649_serial.py`, `tests/test_hotd1_serial_poll.py`, and `tests/test_hotd1_serial_probe.py` compile and execute **artificial** instructions to check mappings, ordering, explicit status injection, and strict refusal.

## What remains unverified

- Original Model 2C RS422 transmit/receive timing and buffer state transitions
- True status reset values, transmit full conditions and receive-ready timing
- Lightgun mux electrical protocol, calibrated X/Y, triggers and offscreen reads
- Complete I/O port mapping, direction and EEPROM interactions
- A native full-original-ROM trace through this routine with a measured cabinet-grounded response
- Graphics coprocessor, sound, video, timers and interrupt behavior

Until those are implemented and tested, **Model 2C is not complete**. There must be no shortcut analogous to emulator fixed-0x0c serial status that makes the game *seem* to boot.
