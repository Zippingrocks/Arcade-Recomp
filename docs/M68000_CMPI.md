# MC68000 immediate comparison: bounded native AOT extension

Status (2026-10-11): CMPI now translates to native C++ for byte, word and long
operands in Dn, `(An)`, `(d16,An)`, absolute-short and absolute-long forms.
This extends sound CPU instruction support; it does not establish sound RAM,
board-control semantics, physical reset, audio output or cycle timing.

## Independent instruction and bus contract

The implementation follows Motorola's
[M68000 Family Programmer's Reference Manual](https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf),
printed pages 4-79–4-80 and 2-18–2-19. CMPI calculates destination minus
immediate, updates NZVC, preserves X, and does not write its destination. Byte
immediates use the extension word's low byte. Absolute-short addresses are
sign-extended. PC-relative CMPI is not an MC68000 instruction and remains
unsupported, as do updating and indexed forms in this bounded subset.

The [MC68000 User's Manual](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf),
section 2.4/Figure 2-6, section 5.1.1 and section 6.3.10, specifies memory
organization, word read transactions, and odd word/long address errors. A long
operand is read high word first, then low word at the next word address. Both
reads independently apply the 24-bit physical address mask. Word reads are
not expanded into byte callbacks.

Generated code fixes the operation, operand width, immediate and addressing
form ahead of time; there is no runtime opcode decoder. Register comparisons
require only the operand-width bits to be known. Memory comparisons require
any consumed address register to be known and actual data from the bus.
Unknown CCR bits are not consumed. A successful comparison defines NZVC while
preserving both X's value and its knownness, all registers and memory.

Unsupported reads stop without committing flags, PC or completion count. A
successful first word read remains externally observable if the second read
fails: there is no rollback of bus side effects. Fault metadata identifies the
denied word transaction, width 2. An odd long address is refused before any
callback, with operand width 4. These are diagnostic stops, not delivered
hardware exceptions; prefetch and bus timing are still absent.

## Verification

```sh
python -m unittest discover -s tests -p test_m68k_cmpi_native.py -v
python -m unittest discover -s tests -p 'test_m68k*_native.py' -v
```

The five new ROM-free tests cover accepted size/register/address fields,
extension order and truncation, excluded MC68000/later-family modes, every
byte operand pair, word/long boundaries and bit patterns against a separate
wide signed-arithmetic oracle, X value/knownness, unchanged registers, partial
register knownness and strict failure behavior. Memory tests check callback
width and order, signed displacements, 24-bit wrap, alignment, denied first
and second reads, unknown addresses and compare-to-branch paths. Available
GCC and Clang compilers run with undefined-behavior sanitization. The local
GCC/UBSan run passed all five tests without skips.

## Private original-code evidence, not a boot result

The local `epr-19720.31` was authenticated with SHA-1
`1edaed489a3518ddad85728e416319f940ea02bb` and reconstructed with the established
16-bit byte swap. Original sites `0x00600174` and `0x0060017e` contain long
immediate comparisons of absolute-short memory operands `0x00000c08` and
`0x00000c0c`. No original instruction bytes, immediate data or generated code
are distributed with this evidence.

Private GCC/UBSan native checks executed these two original instructions with
**8,192 explicitly synthetic memory/CCR states**, plus three synthetic branch
scenarios and two strict-bus refusal checks. The first mismatch executes two
instructions and reaches the unsupported LEA at `0x0060018c`; a second
mismatch reaches the same stop after four instructions. Matching both supplied
values reaches the unsupported memory-source MOVE at `0x00600188` after four
instructions. A strict bus refuses the first word read of either comparison.
These are isolated site tests, not observed game RAM or continuous startup.

Static discovery from the original explicit vector entry now finds 35 sites,
33 translated and two unsupported at `0x00600188` and `0x0060018c`, without
hitting its limit. Static counts are not dynamic instruction, sound coverage,
or fidelity percentages. Generated original-code validation artifacts remain
private in fresh ignored `build/` subdirectories.

The strict reset-vector probe's 17-instruction SCSP boundary and the opt-in
common-control probe's 18-instruction refusal at the unknown `0x00400001`
board-control write are not bypassed by CMPI. The next instruction-only work
can address the newly exposed MOVE/LEA forms independently. Faithful startup
still requires separate evidence for board control, RAM, reset wiring,
interrupts and SCSP timing/synthesis.
